# CS-255-Portfolio
**Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?**
The client was Liam, the owner of DriverPass, a company that helps people prepare for their driving tests. The project required a web-based system that allows customers to create accounts, select training packages, and schedule lessons with trainers. The system also needed to support different user roles and features such as login and password reset.
**What did you do particularly well?**
I thought I did well at gathering and organizing the client’s requirements into functional and non-functional requirements. This made it easier to understand what the system needed to do before moving into the design phase.
**If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?**
I would probably go back and improve the diagrams. Adding more specific data would make the design easier for someone else to understand. For example I would revise my class diagram. While it includes the main classes and attributes, I would improve it by adding relationships between the different classes.
**How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing?**
I read the client’s interview and requirements carefully. Then I put those needs into my diagrams, like letting users log in, choose packages, and book lessons. It is important to think about what the user needs so the system helps them.
**How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?**
I’ll start by reading the requirements, then create  UML diagrams to plan the system’s design. In the future, I would also get more feedback from the stakeholders.
